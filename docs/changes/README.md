# 项目改动报告与提交规则

## 必须遵守的完成流程

每个逻辑改动任务（代码、配置、构建脚本或文档）完成后，必须先形成项目改动报告，再根据报告及实际 diff 总结 commit 信息。报告、实现和验证不一致时先修正，不得用计划冒充结果。

1. 检查当前分支、HEAD、工作区和暂存区；保留已有修改。
2. 完成授权范围内的实现及与改动相称的验证，冻结待审查版本。
3. 在本目录创建或更新改动报告，记录计划落实情况和实际证据。
4. 对照报告及准备提交的文件清单提炼 commit 信息。
5. 只有得到明确提交授权后才显式暂存、核对暂存 diff 并提交。推送、合并、发布和刷机另需授权。

纯只读查询无需强制新建改动报告。每次文件保存不单独生成报告；同一任务的返工更新同一报告。报告和配套规则的更新计入本任务，不递归产生“报告的报告”。

## 文件命名与必需内容

使用项目时区 Asia/Shanghai，文件名为 `YYYY-MM-DD-主要改动点.md`；日期表示本次交付/集成日期，历史实现和测试日期在正文注明。不同任务同名时使用 `-2`、`-3`，不覆盖其他任务报告。

每份报告包含：

- 目标、背景、计划事项及落实情况；
- 输入版本、完成状态、分支/worktree、集成与部署状态；
- 实际修改文件、关键位置及用户可见行为/兼容性变化；
- 实际执行的命令、输入、结果、退出码，以及必要的文字验证摘要；
- 审查结论、未执行检查、风险、回滚和下一步；
- 与本次实际 diff 对齐的建议 commit 信息。

未知字段明确标注未提供；区分静态检查、主机桩测试、内核编译和实机测试。报告不预填自身所在提交尚不存在的 SHA，可使用基线、补丁/文件哈希和“随本提交落地”；实际提交 SHA 在交付回报中提供。源码引用优先项目相对路径；机器路径只作为历史溯源，不成为测试运行依赖。

## 项目内仅保留说明文档

每次修复只在 `docs/changes/` 保留说明类改动报告；不在项目内归档补丁、测试/回滚脚本、fixtures、原始日志、验证 JSON、哈希清单、二进制或其他实质性文件证据。修复源码本身正常随提交进入相应子系统，不受本条限制。

实际验证仍必须执行，命令、结果、退出码、审查结论和风险以报告文字摘要记录，不能用不保存证据作为跳过检查的理由。底层执行记录如需留存，仅置于仓库外的工作目录，不强制添加、不改名绕过忽略规则，不作为项目可运行入口或可复现产物承诺。历史外部路径只能用于溯源。

## commit 信息来自报告

标题使用 Linux 内核风格：`subsystem: concise English summary`。正文根据报告概括问题、原因、修复行为、真实验证及必要限制，并增加一行：

```text
Report: docs/changes/YYYY-MM-DD-主要改动点.md
```

提交只描述实际暂存内容；拆分提交引用报告对应部分，不将整批历史成果归入无关提交。不虚构 Fixes、CVE、Signed-off-by、Reviewed-by、Tested-by 或未执行的验证。不得绕过 hook；生成消息不代表授权 commit 或 push。显式 `git add` 文件清单，禁止用 `git add .` 混入用户改动。

## GitHub CLI 使用规则

本项目的 GitHub 身份和 GitHub 远端操作统一通过 GitHub CLI（`gh`）处理。提交前用 `gh auth status` 核验登录账号，必要时用 `gh api user` 确认身份；不打印或归档认证 token。

`gh` 没有原生本地 commit 子命令：本地提交由 Git 完成，不能将其误写为执行了 `gh commit`。GitHub PR、远端查询以及经授权的 GitHub API 操作使用 `gh`；不得为了“通过 gh 提交”擅自创建远端 commit、更新远端分支或触发推送。

优先使用已有、与用户意图一致的仓库 Git 身份。缺失时经用户授权，用 `gh api user` 验证的显示名（为空则 login）和 GitHub noreply 身份配置**仓库级** `user.name`/`user.email`，不改全局设置，不根据本机用户名或历史作者猜测。ID 型 noreply 格式按 [GitHub 邮箱规则](https://docs.github.com/en/account-and-profile/reference/email-addresses-reference) 核对。登录账号、已有 Git 身份或目标仓库冲突时先确认，不自动替换或切换账号。

## 本地设置与版本管理

`AGENTS.md`、`CLAUDE.md`、`paseo.json`、`docs/paseo/` 是按现有规则忽略的本地代理配置；同步本规范但不强制纳入 Git。新 worktree 按项目白名单引导配置。正式规则以本文件为可版本化依据；不安装 Git hook，也不把提示规则宣称为强制技术拦截。

不得为归档任务修改 `.gitignore` 或绕过忽略规则；如必要产物被忽略，报告阻塞，等待明确处理授权。
